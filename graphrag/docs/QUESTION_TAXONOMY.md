# Question Taxonomy

Phase 2 classifies only the 100 public evaluation questions. The taxonomy is derived from the observed `qtype` values and question wording in `eval_public.jsonl`; hidden evaluation records and answers are not used.

## Observed Categories

| Dataset label | Count | Complexity | Observed evidence scope | Vector-only conclusion |
| --- | ---: | --- | --- | --- |
| `lookup` | 19 | Direct lookup | One document | Potentially sufficient |
| `multi_hop` | 28 | Multi-hop reasoning | One document with internal clues | Potentially sufficient |
| `temporal` | 22 | Temporal reasoning | Two documents | Not sufficient alone |
| `aggregation` | 21 | Set aggregation | Multiple documents | Not sufficient alone |
| `superlative` | 10 | Set ranking | Multiple documents | Not sufficient alone |

The labels above are dataset-provided categories, not newly invented classifications. Public gold-document counts show that lookup and multi-hop questions have one reference, temporal questions have two, and aggregation/superlative questions generally require a candidate set. The exact per-question analysis is generated by `benchmark/dataset/question_classifier.py`.

## Retrieval Implications

### Lookup

Retrieve the event document matching the event described in the question. A vector or lexical retrieval method may be sufficient when the event description is distinctive, but this is an observed possibility rather than a benchmark result.

### Multi-hop

Resolve multiple clues such as venue, date, and event within the matching event document. The public reference count is one, so “multi-hop” describes reasoning over clues rather than a confirmed multi-document graph traversal.

### Temporal

Resolve a relative Olympic edition such as the edition immediately before a named year, then retrieve the target event. The observed public references contain two documents, supporting a multi-document retrieval requirement.

### Aggregation

Retrieve the complete candidate event set and count records satisfying a threshold. The observed reference counts are greater than one, so one-document retrieval is not an adequate confirmed strategy.

### Superlative

Retrieve the candidate event set and compare a numeric attribute such as competitor count. The observed reference counts are greater than one, so retrieval must preserve a sufficiently broad candidate set before ranking.

## Graph Retrieval Finding

The corpus contains flat identifiers and text, but no explicit entity or relationship arrays. Therefore this phase does not claim that graph traversal is required or available. Every generated analysis records `graph_traversal_requirement: not_confirmed`. Deriving entities or relationships belongs to a later authorized architecture phase.

## Limitations

The taxonomy does not measure answer accuracy, retrieval recall, embedding quality, graph utility, or LLM behavior. Public gold documents are used only to characterize evidence scope. No hidden answers or hidden ground truth are read, copied, or used for tuning.
